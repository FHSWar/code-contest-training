# LC 35 · 搜索插入位置 — 解题思路

## 题意

在**升序、无重复**数组中找 `target` 的下标；若不存在，返回「按顺序插入」的位置。要求 **O(log n)**。

## 核心思路

- 插入位置 = 第一个 **大于等于** `target` 的元素下标；若所有元素都小于 `target`，则为 `n`。
- 这正是经典 **lower_bound**（或 `bisect_left` / `partition_point`）语义，可用与 [LC 704](../704-binary-search/) 中 **左闭右开 `[left, right)`** 相同的二分模板一次写出。

## 模板（左闭右开）

| 项目 | 取值 |
| --- | --- |
| 初值 | `left = 0`, `right = n`（`right` 为「开」端，可指「末尾之后」） |
| 循环 | `while (left < right)` |
| `nums[mid] < target` | `left = mid + 1`（答案在右半段） |
| `nums[mid] >= target` | `right = mid`（收缩到含 `mid` 的左半段，保留「第一个 ≥ target」候选） |
| 结束 | `left === right`，即为插入下标 |

- 若 `target` 在数组中，循环会收缩到其下标。
- 若 `target` 不在数组中，收缩到第一个大于 `target` 的位置之前一格的「右侧」，即第一个 ≥ `target` 的位置；若全部更小，则得到 `n`。

与 704 的 `searchHalfOpen` 相比：704 在相等时**立即返回**；本题在 `nums[mid] >= target` 时统一走 `right = mid`，不提前返回，从而始终收敛到**第一个**满足 `>= target` 的位置。

## 复杂度

- **时间**：O(log n)
- **空间**：O(1)

## 易错点

1. **返回值**：循环结束时 `left` 即为答案（不要误用 `mid`）。
2. **与 704 分支差异**：本题不能在中点等于 `target` 时直接 `return mid` 就结束吗？——可以，但为与「找第一个 ≥」统一、少写分支，常用全程 `right = mid` 的写法；两种等价需注意与模板一致。
3. **`mid` 计算**：仍用 `left + floor((right - left) / 2)`，避免溢出。
